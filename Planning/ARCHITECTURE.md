# Instagram PR Image Generator - アーキテクチャ設計書

## 1. システム概要

Gammaスタイルの「ハイブリッド型デザインエンジン」

**ハイブリッド方式**:
- **セマンティックデザイン**: タグに意味をつけ、LLMが文脈を理解して適切なHTML/CSSを選んで適用
- **セクションテンプレート**: 固定のHTML構造にコンポーネントを合成

**実装するもの**: LangChainを使ったLLMワークフロー

---

## 2. ワークフロー

### 2.1 登録フロー

```
画像 → LLMが構造・タグを解析 → 手動でHTML/CSSテンプレートを紐付け → DB保存
```

### 2.2 生成フロー（3 Phase）

```
┌─────────────────────────────────────────────────────────────────┐
│                      Generation Workflow                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  【入力】                                                         │
│  ├─ タグ（複数）: ["新卒採用", "ポップ", "シンプル"]               │
│  └─ ユーザープロンプト: "新卒採用を開始しました！"                  │
│                                                                  │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ Phase 1: embeddingベクトル検索                            │   │
│  │                                                           │   │
│  │ ユーザー入力タグをembedding                               │   │
│  │     ↓                                                     │   │
│  │ pgvectorで類似コンポーネントを検索                        │   │
│  │     ↓                                                     │   │
│  │ 全候補取得: [comp_A, comp_B, comp_C, ...]                │   │
│  │                                                           │   │
│  │ ※表記揺れ対応: "新入社員" ≈ "新卒社員"                    │   │
│  └──────────────────────────────────────────────────────────┘   │
│                          ↓                                       │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ Phase 2: LLMで競合解決（セマンティックデザイン）           │   │
│  │                                                           │   │
│  │ 同一役割のコンポーネントが複数ある場合                     │   │
│  │     ↓                                                     │   │
│  │ LLMがユーザープロンプトの文脈を解析                       │   │
│  │     ↓                                                     │   │
│  │ 文脈に最も合うものを選択                                  │   │
│  │                                                           │   │
│  │ 例: header_A vs header_B → 文脈的にheader_Aを採用        │   │
│  └──────────────────────────────────────────────────────────┘   │
│                          ↓                                       │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ Phase 3: セクションテンプレートで合成                      │   │
│  │                                                           │   │
│  │ 選択されたコンポーネントを役割ごとに配置                   │   │
│  │ ├─ header: comp_A                                        │   │
│  │ ├─ body:   comp_C                                        │   │
│  │ ├─ cta:    comp_B                                        │   │
│  │ └─ ...                                                   │   │
│  │     ↓                                                     │   │
│  │ 最終HTML/CSS生成                                         │   │
│  └──────────────────────────────────────────────────────────┘   │
│                          ↓                                       │
│  【出力】                                                         │
│  HTML/CSS                                                        │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 3. コンポーネント設計

### 3.1 コンポーネントの役割（role）

| role | 説明 |
|------|------|
| header | ヘッダー部分 |
| body | メインコンテンツ |
| footer | フッター部分 |
| cta | Call to Action |
| color | カラーパレット |
| font | フォントスタイル |
| layout | レイアウト構造 |
| decoration | 装飾要素 |

### 3.2 コンポーネントの構造

```json
{
  "id": "comp_001",
  "name": "採用ヘッダー_ポップ",
  "role": "header",
  "tags_embedding": [0.1, 0.2, ...],  // embeddingベクトル
  "template_html": "<div class='header'>{{title}}</div>",
  "template_css": ".header { background: {{bg_color}}; }",
  "slots": {
    "title": { "type": "text", "max_chars": 20 },
    "bg_color": { "type": "color", "default": "#FF6B6B" }
  }
}
```
