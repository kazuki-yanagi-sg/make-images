この文書は、[WHOLE_POST_TEMPLATE_DESIGN.md](./WHOLE_POST_TEMPLATE_DESIGN.md) を実装に落とすためのTDD計画書とする。

- テストを先に書く

- 通った後にのみ整理する

- 既存コードの都合ではなく、目的適合性を優先する

## 4. 今回のテスト対象

### 4.1 テンプレート登録

- 画像から構造JSONを抽出して保存する
- 手動タグを必須とする
- 自動タグを補助情報として保存する
- 検索用テキストと埋め込みを生成する

### 4.2 テンプレート検索

- 手動タグ一致を優先する
- 手動タグの類似を補助的に扱う
- 自動タグは手動タグより弱く扱う
- `prompt` のみで無関係なテンプレートを選ばない

### 4.3 文言生成

- 構造JSONを壊さない
- 必須スロットを埋める
- 文字数制約を守る

### 4.4 レンダリング

- HTML/CSSを生成する
- UIプレビューに必要な情報を返す

### 4.5 生成履歴

- 入力タグと入力プロンプトを保存する
- 採用テンプレートIDを保存する
- 文言代入後の構造JSONを保存する
- 出力HTML/CSSを保存する

## 5. テスト戦略

## 7. テストケース一覧

### 7.1 受け入れテスト

- [x] 手動タグなしではテンプレート登録できない
- [x] テンプレート画像を登録すると構造JSON、手動タグ、自動タグ、ベクトルが保存される
- [x] `tags + prompt` で生成するとHTML/CSSプレビューが返る
- [x] 生成時に採用テンプレートIDと生成履歴が保存される

### 7.2 テンプレート登録API

- [ ] `name` が空なら400
- [ ] `manual_tags` が空なら400
- [ ] 画像がなければ400
- [ ] 正常系で `template_id` が返る
- [ ] 正常系で `structure_json` が返る
- [ ] 正常系で `preview_html` と `preview_css` が返る

### 7.3 テンプレート検索

- [ ] 手動タグ完全一致が最優先で選ばれる
- [ ] 手動タグが近い候補が次点に残る
- [ ] 自動タグ一致だけの候補は手動タグ一致候補を超えない
- [ ] 同点候補のみベクトル類似で再順位付けされる
- [ ] 手動タグ無関係な候補は除外される

### 7.4 文言生成

- [ ] 必須スロットが全て埋まる
- [ ] `slot.max_chars` を超える場合は短縮される
- [ ] 構造JSONの要素数が変わらない
- [ ] 構造JSONの `id` が変わらない
- [ ] 位置とサイズが維持される

### 7.5 HTML/CSSレンダリング

## 9. 受け入れテストの期待シナリオ

### 9.1 登録

1. ユーザーが画像、名前、手動タグを入力する
2. APIが構造JSONと自動タグを生成する
3. テンプレートが保存される
4. 登録確認用のHTML/CSSが返る

### 9.2 生成

1. ユーザーが `tags` と `prompt` を入力する
2. タグ優先でテンプレート候補が選ばれる
3. 選ばれた構造に対して文言が生成される
4. HTML/CSSプレビューが返る
5. 履歴が保存される

## 10. モック方針

### 10.1 モックしてよいもの

- LLMの構造抽出
- LLMの自動タグ抽出
- LLMの文言生成
- Embedding生成

### 10.2 モックしてはいけないもの

- APIの入力バリデーション
- 検索優先順位のロジック
- 文字数制約
- 構造JSONの不変条件
- レスポンス形式
