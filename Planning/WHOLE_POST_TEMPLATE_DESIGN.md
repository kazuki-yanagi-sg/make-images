# Instagram投稿全体テンプレート方式 詳細設計書

## 1. この設計書の位置づけ

この文書は、今回のマイルストーンにおける詳細設計書とする。
実装、テスト、リファクタリングは本書を基準に進める。

今回採用する保存単位は次で固定する。

- `Instagram投稿1枚 = 1テンプレート`

今回のマイルストーンでは、投稿を `header` `body` `cta` などの部品へ分解して保存する方式は採用しない。

## 3. 解決したい課題

画像だけを保存しても、生成時に `prompt` のみで正しいテンプレートを選ぶのは難しい。
そのため、テンプレートごとに人が付けたタグを持ち、検索時はタグを主軸にする。

責務は次のように分離する。

- 検索: 入力タグと保存タグから適切なテンプレートを選ぶ
- 生成: 選ばれたテンプレート構造に対して文言を作る
- レンダリング: 構造JSONと文言からHTML/CSSを作る
- 表示: UIでプレビューする

## 4. 前提条件

- テンプレート登録時の手動タグは必須
- 生成時の入力は `tags` と `prompt` の両方必須
- 内部の正は構造JSON
- ユーザーに返す成果物はHTML/CSSプレビュー
- テストは現行コードに合わせず、本書の期待動作に対して作る

## 5. 採用方針

### 5.1 採用する方針

- Instagram投稿1枚を丸ごと1テンプレートとして保存する
- 手動タグを検索の主軸とする
- 自動タグは補助情報として扱う
- 類似検索はタグ検索を補強する目的でのみ使う
- 文言生成は選ばれたテンプレート構造の制約内で行う
- 出力はHTML/CSSとして返し、UIでプレビューする

### 5.2 採用しない方針

- `prompt` のみでテンプレート選択を完結させる
- 画像だけを保存してタグを持たない
- 構造JSONを持たずHTML/CSSのみを正とする
- 投稿を複数部品に分解して管理する

## 6. ドメインモデル

### 6.1 Template

Canva等で作られたInstagram投稿1枚分のテンプレート。

保持する責務:

- 元画像との対応
- 構造JSONの保持
- 手動タグと自動タグの保持
- 検索用テキストと検索用ベクトルの保持
- プレビュー用HTML/CSSの保持

### 6.2 Structure JSON

テンプレートの正本データ。
要素の位置、サイズ、役割、スタイル、スロット制約を保持する。

### 6.3 Generation

ユーザー入力に対する1回の生成結果。

保持する責務:

- 入力タグ
- 入力プロンプト
- 採用テンプレートID
- 文言代入後の構造JSON
- 出力HTML/CSS

## 8. 構造JSON詳細仕様

### 8.1 最低限のフォーマット

```json
{
  "canvas": {
    "width": 1080,
    "height": 1080,
    "background_color": "#FFF8F2"
  },
  "elements": [
    {
      "id": "headline",
      "type": "text",
      "role": "headline",
      "x": 120,
      "y": 120,
      "width": 840,
      "height": 180,
      "style": {
        "font_size": 64,
        "font_weight": 700,
        "line_height": 1.2,
        "color": "#111111",
        "align": "center"
      },
      "slot": {
        "name": "headline",
        "required": true,
        "max_chars": 18
      }
    }
  ]
}
```

### 8.2 要素ルール

- `id` はテンプレート内で一意
- `type` は最低限 `text` `image` `shape` を許容
- `role` は意味上の役割を表す
- `slot` がある要素のみ文言差し替え対象とする

### 8.3 不変条件

- 要素数を勝手に変えない
- 既存要素の `id` を変えない
- `x` `y` `width` `height` を勝手に変えない
- `slot.max_chars` を超える文言をそのまま入れない
- レンダリングに必要なキーを削除しない

## 9. タグ仕様

### 9.1 手動タグ

- テンプレート登録時にユーザーが入力する
- 必須
- 検索で最も強いシグナルとして使う

### 9.2 自動タグ

- 画像解析時にLLMが生成する
- 任意
- 手動タグの補助としてのみ使う

### 9.3 タグ正規化

生成時の入力タグに対して最低限次を行う。

- 前後空白除去
- 重複除去
- 空文字除去

必要に応じて将来追加する。

- 表記揺れ辞書
- 同義語辞書
- カテゴリ別タグ

## 10. 検索戦略詳細

### 10.1 優先順位

1. 手動タグ一致
2. 手動タグ類似
3. 自動タグ一致
4. 検索用ベクトル類似

### 10.2 検索アルゴリズム

1. 入力タグを正規化する
2. 手動タグの完全一致数を計算する
3. 手動タグの類似候補を評価する
4. 自動タグ一致を補助点として加える
5. ベクトル類似度で同点候補を再順位付けする
6. 上位1件を採用する

### 10.3 ルール

- 手動タグに全く関係しないテンプレートを、`prompt` だけで選んではならない
- 手動タグ一致候補がある場合、自動タグ一致のみの候補を優先してはならない
- ベクトル検索はタグ検索の代替ではなく補助である

### 10.4 保存する検索結果

- 選ばれたテンプレートID
- 候補テンプレートID一覧
- 各候補の一致タグ
- 各候補のスコア

## 11. 登録フロー詳細

### 11.1 入力

- `name`
- `manual_tags`
- `image`

### 11.2 処理手順

1. 入力バリデーション
2. 画像保存
3. 画像から構造JSON抽出
4. 構造要約抽出
5. 自動タグ抽出
6. 検索用テキスト生成
7. 埋め込み生成
8. プレビューHTML/CSS生成
9. テンプレート保存

### 11.3 登録失敗条件

- 手動タグが空
- 画像形式不正
- 構造抽出失敗
- 保存失敗

## 12. 生成フロー詳細

### 12.1 入力

- `tags`
- `prompt`

### 12.2 処理手順

1. 入力バリデーション
2. タグ正規化
3. テンプレート候補検索
4. 採用テンプレート決定
5. 構造JSON取得
6. 各スロット向け文言生成
7. 制約補正
8. 構造JSONへ代入
9. HTML/CSSレンダリング
10. 生成履歴保存
11. レスポンス返却

### 12.3 生成失敗条件

- `tags` が空
- `prompt` が空
- テンプレート候補なし
- 文言生成失敗
- レンダリング失敗

## 13. 文言生成詳細

### 13.1 入力

- 採用テンプレートの構造JSON
- ユーザープロンプト
- 入力タグ

### 13.2 出力

- 各スロットに対応した文言辞書

例:

```json
{
  "headline": "新卒採用スタート",
  "subheadline": "若い力を募集しています",
  "cta": "詳しくはこちら"
}
```

### 13.3 制約

- `slot.name` 単位で値を返す
- 必須スロットを欠落させない
- 最大文字数を超える場合は短縮する
- 構造JSONのキーを壊さない

## 14. HTML/CSSレンダリング詳細

### 14.1 方針

- 構造JSONを元にHTML/CSSを組み立てる
- HTML/CSSはUIプレビューにそのまま使える形で返す

### 14.2 最低限の責務

- canvasサイズを反映する
- text要素を配置する
- style情報をCSSへ変換する
- slotへ入った文言をHTMLへ反映する

### 14.3 出力

```json
{
  "output_html": "<div class=\"ig-post\">...</div>",
  "output_css": ".ig-post {...}"
}
```

## 15. API詳細

### 15.1 POST /api/templates

用途:
投稿テンプレートを登録する。

リクエスト項目:

- `name`
- `manual_tags`
- `image`

バリデーション:

- `name` が空なら400
- `manual_tags` が空なら400
- `image` がなければ400

レスポンス項目:

- `template_id`
- `manual_tags`
- `auto_tags`
- `structure_json`
- `preview_html`
- `preview_css`

### 15.2 POST /api/generate

用途:
タグとプロンプトから成果物プレビューを生成する。

リクエスト項目:

- `tags`
- `prompt`

バリデーション:

- `tags` が空なら422
- `prompt` が空なら422
- 候補なしなら404

レスポンス項目:

- `generation_id`
- `template_id`
- `matched_tags`
- `filled_structure`
- `output_html`
- `output_css`

## 16. 受け入れ条件

- 手動タグなしではテンプレート登録できない
- 画像から構造JSONを抽出して保存できる
- タグ一致テンプレートが優先して選ばれる
- 無関係なタグのテンプレートは `prompt` だけで選ばれない
- 生成文言が文字数制約内に収まる
- HTML/CSSが返る
- UIプレビューに必要な情報が返る
- 生成履歴が保存される
